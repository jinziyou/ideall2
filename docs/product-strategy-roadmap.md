# ideall 产品定位与路线图

> 状态：GPUI 产品方向与执行基线
> 更新：2026-07-28

## 产品定位

ideall 是一个本地优先的浏览与个人信息工作台：浏览、收集、整理，再让 AI 基于用户明确
授权的资料检索、创作和行动。

产品围绕一条主循环演进：

```text
浏览 / 发现 → 捕获 → 本地整理 → 检索与重访 → AI 综合 / 行动 → 形成个人产物
```

浏览器、笔记、文件、Agent、应用与社区不是彼此竞争的产品线，而是这条循环中的输入、
处理和输出能力。

## 目标用户

首个稳定版本面向高信息密度的个人用户：

- 经常跨网页、文档、文件和 AI 工具研究或学习；
- 保存了大量链接，却难以再次找到和利用；
- 希望资料主要由自己控制，并能离线访问；
- 愿意使用快捷键、标签页和 Agent，但不想维护复杂知识库。

多人实时协作、企业审批、完整项目管理和大型白板暂不进入核心范围。

## 产品原则

### 本地拥有

- 用户创建和捕获的内容默认先写入本机 SQLite。
- 离线时仍能浏览、搜索和编辑本地核心。
- 凭据只进入平台安全存储，不写入数据库、归档或日志。
- 导出、备份和迁移属于核心能力。

### 浏览必须形成资产

- 打开外链只是最低能力；保存、整理和再次利用才是产品价值。
- 保存后的对象应能被搜索、引用、重新打开和加入 AI 上下文。
- 捕获操作保持直接，不用复杂分类表单阻塞用户。

### AI 可见、可控、可回写

- AI 默认只获得最小上下文；私密正文需要显式选择或授权。
- 写操作展示目标并留下脱敏审计。
- 有价值的 AI 结果应能回写为普通笔记、书签或任务。

### 轻创作

- 优先支持标题、段落、引用、列表、任务、代码块和分隔线。
- 编辑器服务“信息到观点/产物”的路径，不追求完整办公套件。
- 未识别的历史块必须可逆保留，不能因编辑而丢失。

### 连接必须可解释

- 模型、同步、ACP、WebView 和外部应用分别说明出站范围与信任边界。
- 无法兑现的能力不显示占位入口。
- 外部进程和 WebView 不获得本地数据的 ambient authority。

## 当前 GPUI 基线

默认分支已经具备：

- macOS、Windows、Linux GPUI 桌面壳；
- iOS、Android gpui-mobile 壳与原生输入代理；
- 侧边导航栏、纵向文件树活动栏和标签内容工作区；
- SQLite Node/Blob、回收快照、FTS5 搜索和 Agent 审计；
- Notion 式可逆块编辑、按后缀优化的文本显示与通用预览；
- 受限 Browser Engine 与系统浏览器降级；
- OpenAI-compatible BYOK、实时 Grant、MCP 工具和外部 ACP；
- HKDF/AES-GCM 分区同步与 V2 归档原子导入；
- 平台安全存储和签名更新清单。

产品不提供仓库、终端或数据库文件专用 Engine；此类文件统一按文本或二进制内容进入现有
Editor/Preview，避免把个人信息工作台扩张成开发与数据库工具。

## 信息架构

一级导航保持五个稳定分区：

| 分区 | 用户问题 | 核心内容 |
| --- | --- | --- |
| 我的 | 我保存和创建了什么？ | 页面、书签、关注、文件 |
| 活动 | 正在进行什么？ | 对话、任务、审计与回收 |
| 浏览 | 我现在要看什么？ | Browser、资讯和社区 |
| 应用 | 我可以调用什么？ | 搜索、外部应用和已授权能力 |
| 设置 | 数据如何被处理？ | 本地数据、同步、AI、安全和更新 |

桌面固定使用“导航栏 → 纵向活动/文件树 → 内容区”。移动端使用导航栈和底部栏，不照搬
桌面 IDE 布局。

## 路线图

### P0：可靠、克制的原生工作台

- [x] GPUI 成为唯一生产实现。
- [x] 活动栏收敛为单列纵向文件树。
- [x] Editor、Preview 与 Browser 从导航层回到 Engine 层。
- [x] SQLite、搜索、安全存储、同步和 Agent 进入共享 Rust 用例。
- [ ] 完成中文 IME、选区、VoiceOver/TalkBack 与安装升级人工矩阵。
- [ ] 建立桌面和移动性能基线：冷启动、首帧、搜索、编辑保存和内存。

验收：核心本地流程在断网时可用；界面不暴露不可兑现操作；五平台门禁稳定。

### P1：捕获与重访

- 统一 Browser、系统打开、拖放和移动分享的捕获入口；
- [x] 书签保存 canonical URL、标题、摘要与捕获时间（捕获后后台抓取页面元数据补全，失败静默；捕获时间取节点 created_at）；
- [x] 收件箱承接未整理内容，不在保存时要求分类（已落地「收集箱」：浏览器一键存书签与新建书签默认进入，回收后可恢复）；
- FTS5 返回稳定摘要、类型过滤和原对象跳转；
- Android/iOS Share Extension 把 URL、图片和文件安全交给 application 用例。

验收：从看到网页到本地保存不超过一次确认；保存内容离线可查找和重开。

### P2：资料驱动的 AI

- 当前文件和搜索结果可显式加入上下文托盘；
- 每个上下文对象显示来源、范围和正文读取状态；
- 比较、总结和研究报告使用同一套有界上下文；
- AI 结果经预览写入普通笔记、书签描述或任务；
- 语义检索只有在 Rust 本地推理、模型供应链和可删除索引闭环后启用。

验收：用户选择多项本地资料生成带来源的新笔记，未选择正文不会进入模型请求。

### P3：可行动的连接

- 外部 ACP/MCP 的能力、最近调用和失败分类对用户可见；
- 本机应用交接逐项完成授权、失败降级和隐私说明；
- 高影响动作绑定真实目标版本，并要求明确确认；
- connector 若引入，必须使用独立签名根、内容寻址包和平台沙箱评估。

验收：连接可以被理解、撤销和降级；卸载连接不破坏已保存内容。

### P4：跨端回顾

- 移动端快速捕获、搜索、阅读和轻编辑；
- 同步范围、冲突和恢复状态可见；
- 提供每日/每周回顾和未处理内容提醒；
- 跨端重复提交不会创建重复对象。

## 指标

北极星指标是“每周被重新利用的个人对象数”：本周被搜索打开、加入 AI 上下文、引用到
笔记或用于动作的已保存对象数量。

配套指标：

- 捕获完成耗时与失败率；
- 保存对象 7/30 天重访率；
- 有结果搜索率和结果点击率；
- 使用本地来源的 AI 会话占比；
- AI 结果转为文件/任务的比例；
- 同步成功率、冲突率和恢复率。

护栏：

- 未经明确动作发送私密正文的次数必须为零；
- 捕获、索引或同步导致的源数据丢失必须为零；
- 后端不可用时本地捕获、搜索和编辑继续工作；
- 新能力不得持续恶化冷启动、首帧和输入延迟。

## 工程准则

- 新体验经 application/FileSystem 用例，不从 GPUI View 直接访问 SQLite。
- FileRef 是稳定身份；路径、名称和目录项只是投影。
- 索引是可删除派生数据，损坏时回退源数据并可重建。
- 每个里程碑提供聚焦单测、GPUI 冒烟和真实平台验收。
- 新连接同时定义信任来源、权限、撤销、离线降级和数据出站。
- 产品现状以代码与本文件为准；旧 Tauri 路线记录只存在于 `legacy/tauri-v2`。
